# ⚙️ Руководство по настройке проекта Sparky (CrazyGerman)

Это руководство описывает структуру и назначение файлов конфигурации, расположенных в скрытой директории `.german` (или `.sparky`) в корне каждого проекта. Эти файлы содержат настройки, специфичные для данного проекта, и могут переопределять глобальные настройки плагина.

**Расположение директории:**
`file://~project/.german/` (или `file://~project/.sparky/` как фоллбэк)

---

## 1. Общая структура директории `.german`

```
.german/
├── config.json           # Настройки игнорирования файлов для FileTree
├── profile.json          # Профиль проекта (архитектура, концепция, особенности)
├── trainers.json         # Список файлов-тренеров для ИИ
├── project_map.md        # Структура ментальной карты проекта
└── map_config.json       # Конфигурация канбан-доски для ментальной карты
```

---

## 2. `config.json` — Настройки проекта

Этот файл содержит общие настройки для текущего проекта.

* **Расположение:** `file://~project/.german/config.json`
* **Тип:** `JSON-объект`

Пример:
```json
{
  "AlwaysSend": {
    "ProjectFileTree": false
  },
  "ignore_paths": [
    "build/",
    "dist/",
    "target/",
    "out/",
    "nbbackgroundwork/",
    "vendor/",
    "node_modules/"
  ]
}
```

Поля:
*   `AlwaysSend/ProjectFileTree`: `boolean` (опционально)
    *   Переопределяет глобальную настройку `Session/AlwaysSend/ProjectFileTree` из `settings.json`. Если `true`, дерево файлов проекта будет автоматически отправляться ИИ.
*   `ignore_paths`: `array<string>` (опционально)
    *   Список путей (директорий или файлов), которые будут игнорироваться при построении текстового дерева файлов проекта (`file://~project/:tree`). Пути указываются относительно корня проекта.

---

## 3. `profile.json` — Профиль проекта

Этот файл содержит высокоуровневое описание проекта, его архитектурные особенности, концепцию и другие важные детали, которые помогают ИИ лучше понимать контекст.

* **Расположение:** `file://~project/.german/profile.json`
* **Тип:** `JSON-объект`

Пример:
```json
{
  "name": "org.sparky",
  "display_name": "Sparky",
  "concept": "Плагин Sparky является цифровым аватаром автора...",
  "architecture": "При создании ProjectTopComponent через главное меню без аргументов теперь автоматически подтягивается первый открытый в IDE проект через ideHandler.",
  "aiModelHandler": "Реализована динамическая подстановка {$model} и {$apikey} в вебхуки провайдеров, а также поддержка массивов API-ключей с кэшированием выбранного ключа на уровне экземпляра."
}
```

Поля:
*   `name`: `string`
    *   Уникальное имя проекта (например, `org.sparky`).
*   `display_name`: `string`
    *   Человекочитаемое название проекта.
*   `concept`: `string`
    *   Краткое описание основной идеи или концепции проекта.
*   `architecture`: `string`
    *   Описание ключевых архитектурных решений или особенностей проекта.
*   `aiModelHandler`: `string`
    *   Описание особенностей реализации `aiModelHandler` в контексте данного проекта (если есть специфические доработки).
*   `frontend_development_environment`: `string`
    *   Описание среды разработки фронтенда, если она специфична для проекта.
*   `changes`: `object`
    *   Автоматически поддерживаемый плагином лог изменений для полей профиля. Не редактировать вручную.

## 4. `trainers.json` — Список файлов-тренеров

Этот файл содержит список дополнительных Markdown-файлов, которые ИИ должен изучить для получения специфического контекста по проекту.

* **Расположение:** `file://~project/.german/trainers.json`
* **Тип:** `JSON-массив объектов`

Пример:
```json
[
  {
    "file": "file://~project/src/crazy/module/german/PROJECT.md",
    "required": false
  },
  {
    "title": "Core Structure & API Reference",
    "file": "file://~project/src/crazy/module/german/CLASSES.md",
    "required": true
  }
]
```

Поля каждого объекта в массиве:
*   `file`: `string` (URI)
    *   URI к файлу-тренеру. Может быть относительным (`file://~project/...`) или абсолютным (`file:///...`).
*   `title`: `string` (опционально)
    *   Человекочитаемое название тренера, используемое в UI.
*   `required`: `boolean`
    *   Если `true`, файл будет автоматически загружен в контекст ИИ при каждой сессии. Если `false`, файл будет загружен только по явному запросу ИИ.

## 5. `project_map.md` — Ментальная карта проекта

Этот Markdown-файл хранит древовидную структуру ментальной карты проекта. Он является основным источником истины для топологии задач, модулей и идей.

* **Расположение:** `file://~project/.german/project_map.md`
* **Тип:** `Markdown-файл`

**Важно:** Подробные правила синтаксиса и структуры узлов описаны в системной инструкции `system://~prompts/ai_project_map_guide.md`. ИИ должен строго следовать этим правилам при редактировании файла.

Ключевые особенности:
*   Каждый узел представлен заголовком `# Название узла`.
*   Метаданные узлов (ID, родительский ID, тип, данные) хранятся в виде списка атрибутов `- key: value` под заголовком.
*   Иерархия строится по полю `parentid`.
*   Содержит информацию о задачах (`type: task`), модулях (`type: module`), вехах (`type: milestone`) и других элементах проекта.

---

## 6. `map_config.json` — Конфигурация ментальной карты

Этот файл содержит настройки, специфичные для отображения ментальной карты, такие как конфигурация канбан-колонок.

* **Расположение:** `file://~project/.german/map_config.json`
* **Тип:** `JSON-объект`

Пример:
```json
{
  "kanban_settings": {
    "lists": [
      {
        "code": "workflow",
        "title": "Статус",
        "options": [
          { "value": "todo", "title": "В работе" },
          { "value": "done", "title": "Готово" }
        ]
      },
      {
        "code": "priority",
        "title": "Приоритет",
        "options": [
          { "value": "low", "title": "Низкий" },
          { "value": "high", "title": "Высокий" }
        ]
      }
    ]
  }
}
```

Поля:
*   `kanban_settings/lists`: `array<object>`
    *   Массив объектов, каждый из которых описывает одну канбан-колонку или список выбора для задач.
    *   `code`: `string` - Уникальный идентификатор списка (например, `workflow`, `priority`).
    *   `title`: `string` - Человекочитаемое название списка.
    *   `options`: `array<object>` - Массив доступных опций для этого списка.
        *   `value`: `string` - Значение опции, которое будет храниться в поле `data.kanbans[].value` узла задачи.
        *   `title`: `string` - Человекочитаемое название опции.
