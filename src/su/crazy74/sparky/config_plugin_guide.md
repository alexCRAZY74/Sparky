# ⚙️ Руководство по настройке плагина Sparky (CrazyGerman)

Это руководство описывает структуру и назначение файла `settings.json`, который содержит глобальные настройки плагина Sparky. Эти настройки применяются ко всем проектам и сессиям чата, если не переопределены на уровне проекта.

**Расположение файла:**
`file://~user/config/crazy_sparky/settings.json`

---

## 1. Общая структура `settings.json`

Файл `settings.json` представляет собой JSON-объект, содержащий различные секции для конфигурации поведения плагина.

Пример базовой структуры:
```json
{
  "language": "ru",
  "defaultCompany": {
    "ai-models": {
      "gemini-2.5-flash": {
        "default": true,
        "title": "Gemini 2.5 Flash",
        "provider": "google-gemini",
        "model": "gemini-2.5-flash"
      }
    },
    "ai-providers": {
      "google-gemini": {
        "transport": "gemini",
        "webhook": "https://generativelanguage.googleapis.com/v1beta/models/{$model}:generateContent?key={$apikey}",
        "apikey": "YOUR_GEMINI_API_KEY"
      }
    }
  },
  "Session": {
    "AlwaysSend": {
      "OpenTabs": false,
      "ProjectInfo": true,
      "ProjectFileTree": false
    }
  }
}
```

---

## 2. Секция `language`

* **Путь:** `language`
* **Тип:** `string`
* **Описание:** Определяет язык интерфейса плагина. Поддерживаемые значения: `ru`, `en`.

---

## 3. Секция `defaultCompany` — Настройки ИИ-провайдеров и моделей

Эта секция содержит конфигурацию для взаимодействия с различными ИИ-моделями и их провайдерами.

### 3.1. `defaultCompany/ai-models` — Конфигурация моделей ИИ

Каждый ключ в этом объекте представляет собой идентификатор модели.

* **Путь:** `defaultCompany/ai-models/<model_id>`
* **Тип:** `object`
* **Описание:** Объект с настройками конкретной ИИ-модели.

Поля объекта модели:
*   `default`: `boolean` (опционально)
    *   Если `true`, эта модель будет выбрана по умолчанию при старте новой сессии, если пользователь не указал другую. Должна быть только одна модель с `default: true`.
*   `skip`: `boolean` (опционально)
    *   Если `true`, модель не будет отображаться в списке доступных моделей для выбора.
*   `title`: `string` (опционально)
    *   Человекочитаемое название модели, отображаемое в UI. Если не указано, используется `model_id`.
*   `provider`: `string` (обязательно)
    *   Идентификатор провайдера, к которому относится эта модель. Должен соответствовать ключу в секции `defaultCompany/ai-providers`.
*   `model`: `string` (опционально)
    *   Фактическое имя модели, которое будет подставляться в URL вебхука провайдера вместо `{$model}`. Если не указано, используется `model_id`.

### 3.2. `defaultCompany/ai-providers` — Конфигурация провайдеров ИИ

Каждый ключ в этом объекте представляет собой идентификатор провайдера.

* **Путь:** `defaultCompany/ai-providers/<provider_id>`
* **Тип:** `object`
* **Описание:** Объект с настройками конкретного ИИ-провайдера.

Поля объекта провайдера:
*   `transport`: `string` (обязательно)
    *   Тип транспортного протокола для взаимодействия с API.
    *   Поддерживаемые значения:
        *   `openai`: Для OpenAI-совместимых API.
        *   `gemini`: Для Google Gemini API (текущая версия).
        *   `gemini_v1`: Для Google Gemini API (старая версия, если требуется).
        *   Любое другое значение или отсутствие поля: Активирует `DebugEmulator` (локальный эмулятор для отладки).
*   `authorization`: `string` (опционально)
    *   Тип авторизации (например, `Bearer`). Используется для формирования заголовка `Authorization`.
*   `webhook`: `string` (обязательно)
    *   URL конечной точки API провайдера.
    *   Поддерживает подстановки:
        *   `{$model}`: Будет заменено на значение поля `model` из соответствующей конфигурации `ai-models`.
        *   `{$apikey}`: Будет заменено на значение из поля `apikey` этого провайдера.
*   `apikey`: `string` или `array<string>` (обязательно)
    *   API-ключ для доступа к провайдеру.
    *   Может быть одной строкой или массивом строк. Если это массив, плагин будет использовать первый доступный ключ.

---

## 4. Секция `Session/AlwaysSend` — Настройки отправки контекста

Эта секция управляет тем, какие данные автоматически отправляются ИИ в начале каждой сессии или итерации.

*   `OpenTabs`: `boolean`
    *   Если `true`, список всех открытых вкладок в IDE будет отправляться ИИ.
*   `ProjectInfo`: `boolean`
    *   Если `true`, метаданные текущего проекта (имя, отображаемое имя, путь к папке) будут отправляться ИИ.
*   `ProjectFileTree`: `boolean`
    *   Если `true`, текстовое дерево файлов текущего проекта будет отправляться ИИ. **Внимание:** Отправка большого дерева файлов может значительно увеличить размер контекста и стоимость запросов. Рекомендуется держать `false` и запрашивать дерево по необходимости.
