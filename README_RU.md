# 💠 Искра (Sparky)

**Инструмент планирования и инженерный ИИ-ассистент для NetBeans**

---

## 📖 Что это такое

Sparky — инструмент планирования и разработки внутри Apache NetBeans, рассчитанный на одиночную и совместную работу.

Интерактивная ментальная карта проекта хранится непосредственно в репозитории в формате Markdown. ИИ-ассистент опирается на эту карту: он видит модули, задачи и их статусы и решает конкретную задачу в контексте всей системы. Правила разработки команда фиксирует в файлах-тренерах, и ассистент работает в этих рамках.

---

## 🎯 Отличия подхода

* **Структура проекта вместо поиска по фрагментам.** Векторного индекса и нарезки кода нет. Через `project_map.md` модель видит дерево модулей, канбан-статусы и задачи, а нужные файлы запрашивает сама через `needs` и получает их целиком.
* **Опыт команды в файлах-тренерах.** Ведущие разработчики фиксируют стандарты, шаблоны и правила обработки ошибок. Ассистент запрашивает нужный тренер под конкретную задачу, поэтому лишнего и шаблонного кода получается меньше, а уровень кода выравнивается по всей команде.
* **Безопасное внесение изменений.** Модель работает через точечные патчи, без перезаписи файлов целиком. Перед любым изменением создаётся резервная копия.
* **Хранение в Git, без привязки к сервису.** Карта, задачи, настройки и резервные копии лежат в обычных файлах Markdown и JSON. Подписки на плагин нет: оплачивается только использование выбранного API.

## ✨ Ключевые особенности

### 🗺️ Планирование через ментальные карты

* Визуализация модулей, архитектуры, идей и задач (jsMind) прямо в окне IDE.
* Канбан-статусы и временные интервалы на узлах задач.
* Тяжёлые данные задачи (патчи, изменённые файлы, контекст ИИ) загружаются по требованию при выборе узла.

### 👥 Совместная работа через Git

* Карта хранится в репозитории (`.sparky/project_map.md`) в виде плоского иерархического Markdown-списка.
* Планы и задачи синхронизируются обычными коммитами и ветками. История изменений плана совпадает с историей репозитория.

### 🧠 Ассистент с контекстом всего проекта

* **Итерационный протокол `needs`.** Ассистент сам указывает, какие файлы, ресурсы IDE или файлы-тренеры ему нужны, получает их и продолжает работу.
* **Работа с картой.** Ассистент правит `project_map.md` теми же точечными патчами, что и код: обновляет статус задачи или составляет первоначальный план проекта.
* **Несколько провайдеров.** Поддерживаются Gemini и OpenAI-совместимые API. Запросы идут напрямую провайдеру по REST API, адрес и модель задаются в конфигурации; собственного сервера у плагина нет.

### 🛡️ Теневое резервное копирование

* Копия файла создаётся автоматически **до** передачи содержимого ИИ или внесения правок, а также вручную через контекстное меню.
* Структура каталогов сохраняется, версии различаются меткой времени: `.имя_файла.расширение.yyyy-MM-dd_HH-mm-ss.bak`. Каталог `.backup/` исключён из Git.

## 🎓 Файлы-тренеры

Файл-тренер — это текстовая инструкция для ИИ, составленная человеком, который хорошо знает проект и его архитектуру.

1. **Создание.** Более сильные программисты команды описывают правила: как писать сервисы, как обрабатывать ошибки, как структурировать модули. Знания лидов остаются в репозитории и работают на всю команду.
2. **Индекс.** Доступные тренеры перечислены в `trainers.json`. По умолчанию ассистент видит этот список при каждом запросе. Поведение настраивается.
3. **Использование.** Ассистент запрашивает нужный тренер через `needs`, когда задача этого требует. Составить список так, чтобы ИИ понимал, что и в каком случае запрашивать, — задача лидов.

## 🏗 Архитектура

Система построена на слабой связности: компоненты взаимодействуют через интерфейсы и универсальную структуру данных `Storage`.

| Компонент | Назначение |
| --- | --- |
| `BrainHandler` | Ведёт итерационный диалог с ИИ и обрабатывает запросы `needs` |
| `ProjectHandler` | Управляет контекстом проекта и теневыми резервными копиями |
| `aiModelHandler` | Диспетчер моделей и провайдеров ИИ (Gemini, OpenAI-совместимые API) |
| `StoredNotes` | Долгосрочная память с историей изменений |
| `Storage` | Иерархическое хранилище с адресацией по путям (`key/subkey/0`) |
| `JSBridge` | Двусторонняя связь Java ↔ WebView |

### Протокол итерационного взаимодействия

```text
Пользователь ──(запрос)──> BrainHandler ──(контекст)──> ИИ-модель
                                │                           │
                                │<──────(список needs)──────┘
                                │
                         ProjectHandler
                                │
                  резервная копия ──> payload ──> ИИ-модель
                                                      │
                          применение патча <──(ответ)─┘
```

Ход выполнения отображается в интерфейсе через `stages` (`wait`, `process`, `done`). Блок `profile_update` в ответе обновляет долгосрочную память.
