## 📖 Что это такое

Sparky — прежде всего инструмент планирования, как для одиночной, так и для совместной работы. План проекта живёт внутри IDE в виде интерактивной ментальной карты, а хранится в репозитории обычным Markdown-файлом.

Поверх плана работает ИИ-ассистент. Он видит всю карту проекта, открытые вкладки и структуру файлов, поэтому решает задачу в контексте всей системы, а не отдельного фрагмента кода.

Ориентир проекта: реальный результат, чёткая структура и полезное действие в кодовой базе.

## ✨ Ключевые особенности

### 🗺️ Планирование через ментальные карты
* Интерактивная визуализация модулей, архитектуры, идей, заметок и задач прямо в рабочем окне IDE.
* Канбан-статусы и временные интервалы на узлах задач.
* Тяжёлые данные задачи (изменённые файлы, патчи, трудозатраты, контекст ИИ) хранятся отдельно от карты и загружаются при выборе узла.

### 👥 Совместная работа через Git
* Карта хранится в репозитории в формате Markdown (`project_map.md`) в виде плоского списка узлов с указанием родителя.
* Команда синхронизирует планы и архитектурные изменения обычными коммитами и ветками, без внешних облачных сервисов и сторонних трекеров.
* История изменений плана совпадает с историей репозитория: видно, когда и почему сместились приоритеты.

### 🧠 Ассистент, который знает весь проект
* Ассистент постоянно обращается к ментальной карте и благодаря общему контексту решает конкретную задачу осмысленнее.
* **Итерационный сбор контекста.** Ассистент сам указывает, какие файлы и ресурсы IDE ему нужны, получает их и продолжает работу.
* **Карта правится так же, как код.** `project_map.md` для ассистента — обычный файл: статусы, подзадачи и архитектурные решения вносятся теми же точечными патчами. Начальную структуру и план задач можно получить по описанию.
* Работа с несколькими провайдерами ИИ (Gemini, OpenAI-совместимые API) через единый интерфейс; модель выбирается настройками проекта и сессии.

### 🎓 Файлы-тренеры
* Опытные разработчики команды описывают в файлах-тренерах правила и примеры: как в проекте принято писать сервисы, обрабатывать ошибки, структурировать модули.
* Ассистент работает в этих рамках, поэтому лишнего и шаблонного кода получается меньше, а опыт сильных программистов подтягивает всю команду.
* Подробнее — в разделе ниже.

### 🛡️ Безопасность изменений
* **Точечные патчи.** Изменения вносятся в нужные места файла, без перезаписи файла целиком.
* **Теневое резервное копирование.** Копия файла создаётся до того, как его содержимое будет передано ИИ или изменено. Структура каталогов сохраняется, версии различаются меткой времени: `.имя_файла.расширение.yyyy-MM-dd_HH-mm-ss.bak`. Каталог копий исключён из Git.

### 🔒 Изолированный контекст
* Долгосрочная память, архитектурные заметки и конфигурация моделей хранятся локально, в рабочем пространстве проекта и в пользовательском каталоге NetBeans.
* Настройки двухслойные: пользовательские значения приоритетнее системных значений среды.

## 🎓 Файлы-тренеры

Файл-тренер — это инструкция для ИИ, написанная человеком, который хорошо знает проект: правила, паттерны, живые примеры из кодовой базы.

* **Кто пишет.** Файлы разрабатывают более сильные программисты команды. Знания лидов фиксируются в репозитории и работают на всю команду.
* **Как подключаются.** Индекс доступных тренеров хранится в `trainers.json`. По умолчанию при каждом запросе ассистент видит список тренеров и сам запрашивает нужный через механизм `needs`.
* **Зона ответственности лидов.** Составить список так, чтобы ИИ понимал, что и в каком случае запрашивать, — задача тех, кто ведёт проект. Поведение настраивается.

## 🏗 Архитектура

Система строится на слабой связности: компоненты взаимодействуют через интерфейсы и универсальную структуру данных `Storage`.

| Компонент | Назначение |
|---|---|
| `BrainHandler` | Центральный процессор: ведёт итерационный диалог с ИИ, доставляет запрошенные ресурсы |
| `ProjectHandler` | Управляет контекстом проекта и резервным копированием |
| `aiModelHandler` | Диспетчер моделей и провайдеров ИИ |
| `StoredNotes` | Долгосрочная память с историей изменений |
| `Storage` | Универсальное хранилище с навигацией по путям вида `key/subkey/0` |
| `JSBridge` | Двусторонняя связь Java ↔ WebView |

### Протокол итерационного взаимодействия

1. Пользователь отправляет запрос.
2. ИИ отвечает списком `needs` — ресурсов, которые ему нужны (`file://...`, `ide://...`).
3. IDE упаковывает их в `payload` и возвращает ИИ; перед этим изменяемые данные резервируются.
4. Ход выполнения отображается в интерфейсе через `stages` (`wait`, `process`, `done`).
5. Блок `profile_update` в ответе обновляет долгосрочную память.
